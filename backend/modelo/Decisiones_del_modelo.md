# Decisiones e integración del backend

Se integraron las 56 tablas, 451 columnas, 30 enums y 123 relaciones del DBML que contiene el proyecto. Se conservan las capas y namespaces existentes, BaseEntity en update.Domain/Common, GenericRepository, los métodos de negocio de Usuario, su búsqueda por correo y los endpoints de salud. La ruta /api/Users se conserva como alias de /api/usuarios; sus IDs ahora son Guid y sus respuestas no incluyen hashes.

1. BaseEntity usa Guid vacío para que PostgreSQL genere UUID mediante gen_random_uuid(). Usuarios y emprendimientos reciben el UUID del perfil que debe crearse primero. Las entidades con PK numérica, texto o compuesta implementan IEntidadValidable sin introducir columnas ficticias. Las propiedades heredadas que no aparecen en la tabla se ignoran mediante Fluent API.
2. Los enums usan ValueConverter<TEnum,string> con HasConversion(new ConversorEnumDbml<TEnum>()). Se mantienen sus etiquetas originales snake_case; una conversión estándar sin este adaptador produciría nombres PascalCase. La base creada por EF almacena esos campos como text con CHECK, según la instrucción de conversión a string.
3. text no tiene longitudes en el DBML. Los límites propuestos se documentan en limites_texto_propuestos.csv y se aplican tanto en DTO y dominio como mediante HasMaxLength y CHECK char_length. char/varchar mantienen los límites definidos. El índice funcional lower(correo) permite la consulta de usuario sin distinguir mayúsculas.
4. El archivo original bases-de-datos/update.sql confirma las fórmulas: cotizacion_items.total_linea = cantidad * precio_unitario y cotizaciones.total = subtotal - descuento + impuesto. Se usan columnas STORED. Subtotal se recibe explícitamente; no existe un flujo que sume automáticamente todos los items.
5. Las seis columnas identity usan GENERATED ALWAYS AS IDENTITY, como el SQL original: categorias.id, ciudades.id, departamentos.id, etiquetas.id, historial_solicitudes.id y solicitudes_cotizacion.numero. Los DTO no permiten asignar esos valores generados.
6. El esquema no declara ON DELETE. Se propone Cascade para detalles dependientes de su padre y Restrict en referencias cruzadas, autores y catálogos. decisiones_referenciales.csv lista las 123 decisiones. Ocho tablas con eliminado_en implementan borrado lógico y filtro global; este borrado no propaga marcas a las filas relacionadas.
7. Se usa DateTime.UtcNow y precisión de microsegundos para timestamptz; date usa DateOnly. SaveChanges conserva creado_en en actualización. Los DTO de escritura no aceptan auditoría, valores calculados ni alteraciones de PK.
8. El CRUD es administrativo: requiere JWT con rol administrador. Se conserva Swagger en desarrollo con botón Authorize, CORS para localhost:5173 con credenciales y /health, /health/live, /health/ready. No se implementó registro/login ni autorización por propietario. La autenticación del frontend continúa en su modo de demostración original.
9. Se conserva intacta la migración CreateUsuariosTable. ImplementarModeloUpDate renombra Usuarios/columnas, convierte enums numéricos a texto por su significado, completa actualizado_en nulo con creado_en y crea un perfil de persona por cada usuario anterior, conservando UUID y auditoría. El nombre inicial de perfil es u_ seguido del UUID sin guiones; su nombre visible inicial es el correo y puede editarse.
10. La transición rechaza usuarios anteriores con TipoPerfil distinto de Persona, roles fuera de 0/1/2 o correos de más de 254 caracteres antes de modificar sus datos. Down comprueba que el hash se ajuste al límite y nulabilidad anteriores. Las pruebas verifican migración desde cero, con datos anteriores, idempotencia, reversión/reaplicación y rechazo sin pérdida de una fila incompatible.
11. Los archivos SQL originales permanecen como documentación del diseño con enums nativos. Para este backend se usan migraciones EF. Si ya creaste las 56 tablas ejecutando update.sql, esa base tiene un punto de partida distinto de CreateUsuariosTable y necesita una transición específica; no ejecutes la migración inicial sobre ella. No se modificó una base externa o tu PC durante las pruebas.
12. Los commits se separan por tabla e incluyen entidad, configuración, interfaz, repositorio, DTO, controlador, DbSet y registro de DI. Las tablas tienen referencias cruzadas: importa la rama completa para disponer de todas sus dependencias.
